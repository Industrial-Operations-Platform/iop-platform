# Local platform completion

[IOP-203](../planning/items/IOP-203-platform-completion.md) coordinates the
owner-authorized development increment on `feature/IOP-203-platform-completion`.
Run `npm run local:up` to build and migrate the local installation. Existing
records and private references are preserved; the command does not publish code.

Administrator, Team Leader and Task Force use the advanced workspaces. The current
profile and module grants are both required on the server. Administrator alone
manages integration configuration and local operating jobs. Technician journal
and daily planning remain governed by their existing permissions.

The installation contains 71 private equipment schematics and a legend. Initial
geometry traces are available for three views; the other reference scenes are
editable placeholders. The independent diagrams have no measured common origin.
The 3D area overview therefore provides navigation tiles, while each scene uses
coordinates relative to its own reference. It does not claim a registered 3D
floorplan. Screenshot colors are historical; problem markers come from separately
authorized, dated operational records.

Validated local delivery includes API 509, frontend 192, PostgreSQL 319 and final
browser 57 passing checks. Actual encrypted recovery reconciles 170 private files,
62 tables and 154,341 rows, with exact data, role, RLS and privilege metadata. Its
restored database remains isolated and stopped; the active installation is preserved.
See the [completed execution](../planning/completed/IOP-203-platform-completion-plan.md)
for commands, evidence and the final test-only browser correction.

## Remaining input register

| Input or decision | Required to finish |
| --- | --- |
| Measured plant layout, scale, common origin/orientation and floor elevations | Register separate drawings in one physical plant coordinate system. |
| Surveyed sensor positions and validated canonical identities | Confirm exact placement and equipment-to-registry links. Existing source codes remain evidence, not automatic identity approval. |
| Provider API/schema/version, approved access and credentials | Implement and verify real WinCC/Ultimo/Entra transports. Adapter readiness does not imply connection success. |
| Real shift assignments and incoming managers | Operate formal transfers; no shifts are invented from alarms or calendar dates. |
| Intervention dates, owners, targets and production exposure | Evaluate real improvement actions. Imported-date comparisons do not establish causality or plant downtime. |
| Representative workloads, agreed performance thresholds and pilot measurements | Accept operational performance and release criteria. Local measurements alone are insufficient. |
| Organization and platform security Audit operating contract | Finish organization capture and the separate security authority, collection and retention paths. Site material events are already captured. |
| Owner review and remote publication decision | Promote the review branch and publish; stage/master promotion and hosted deployment remain separate. |

Keep incomplete inputs visible in each owning workspace. Do not replace them with
apparently measured coordinates, successful connections or zero-failure metrics.
